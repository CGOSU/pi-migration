## 已确认决策

### 2026-10-11：MCP server 配置不参与迁移

- **决定：** 导出跳过 `mcp.json`，共享 portable-path 校验也将它视为排除数据；导入不恢复目标 MCP 配置，含 MCP 配置文件的旧快照会在任何目标写入或安装前拒绝。
- **原因：** MCP server 命令/参数可能绑定旧机器路径，也可能包含凭据；用户明确要求 MCP 配置不纳入迁移。跳过而不是尝试转换，可避免迁移旧主机路径或认证信息。
- **约束：** 不修改源机或目标机 Pi 的 `mcp.json`。需要 MCP 工具时由用户在新环境自行配置；其他受支持配置的迁移流程保持不变。实现和使用边界见 [`implementation-plan.md`](implementation-plan.md) 与 [`README.md`](../README.md)。

### 2026-10-11：快照只恢复显式支持的非敏感配置，外部 package 安装与文件恢复分离

- **决定：** 使用 schema v1 manifest 和 SHA-256 校验，先验证完整快照，再按可移植相对路径恢复明确支持的配置与本地资源；不复制整个 home/agent 目录。本地 package 的 `package.json` 含 `dependencies` 时，当前实现因无法解析其完整依赖闭包而保守地在写入前拒绝导入。远程 npm/Git package 仅通过目标机 Pi CLI 安装，过滤配置在安装后按快照重建。导入冲突默认拒绝；显式覆盖先备份受影响的非敏感文件。
- **原因：** 本地资源需要保留实际内容，而外部 package 的下载/安装是独立副作用；分离两类数据可以避免将凭据、会话、缓存或不可移植路径当成可恢复内容，也能诚实表达部分失败。
- **约束：** 认证、登录状态、会话、trust 数据和其他敏感运行时状态始终排除；dry-run 不写入、不安装、不执行迁移内容；第三方安装副作用不承诺完整回滚。新环境仍需用户手动 `/login`，Plus 能否使用由人工验证，不由迁移工具承诺。实现与验证细节见 [`implementation-plan.md`](implementation-plan.md)。
